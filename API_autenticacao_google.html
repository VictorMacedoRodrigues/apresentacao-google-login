Nos bastidores

A credencial por trás da tela

O Google retorna um ID Token no formato JWT, com informações sobre a identidade.

ESTRUTURA ILUSTRATIVA DO TOKEN
headerCabeçalho
payloadDados
signatureAssinatura

O campo credential contém o JWT. O payload traz os dados usados para personalizar a tela.

PAYLOAD · EXEMPLO FICTÍCIO
{ "name": "Pessoa Exemplo", "email": "pessoa@example.com", "picture": "https://.../foto.jpg", "sub": "identificador-da-conta" }

Exemplo fictício. O token real não aparece na apresentação.

Boas práticas

Segurança além do botão

Em produção, o servidor verifica a credencial antes de conceder acesso aos dados.

NESTA DEMONSTRAÇÃO

Exibição do perfil

  1. Exibe o botão oficial de login.
  2. Recebe uma credencial no navegador.
  3. Interpreta campos para apresentar o perfil.
  4. Não guarda tokens nem protege dados privados.
EM PRODUÇÃO

Verificação e sessão

  1. Enviar o ID Token por HTTPS ao servidor.
  2. Verificar assinatura, emissor, audiência e expiração.
  3. Identificar a conta pelo campo sub.
  4. Criar uma sessão segura e aplicar permissões.

Decodificar ≠ validar. O Client ID é público. O Client Secret deve ficar fora do navegador.
