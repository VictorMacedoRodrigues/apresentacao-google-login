O serviço

Google Identity Services

Conjunto de ferramentas do Google para adicionar login ao site.

Conta existente

A pessoa usa a própria conta Google.

Senha no Google

O site não recebe a senha dessa conta.

Perfil básico

O site pode receber nome, e-mail e foto.

Esse login, por si só, não concede acesso ao Gmail ou ao Drive.

A escolha do site

Por que usar o Google?

01 / FACILIDADE

Menos cadastro

A pessoa usa uma conta existente e não precisa criar outra senha para o site.

02 / IDENTIDADE

Reconhecer a conta

O identificador sub permite associar a conta Google ao usuário do site.

03 / INTEGRAÇÃO

Reutilizar um serviço

O Google conduz a entrada na conta. O site integra o componente oficial e recebe a credencial.

No nosso portal de estudos, o login personaliza o perfil e reduz etapas de cadastro. Em produção, o servidor ainda precisa validar o token e controlar o acesso.

O processo

O que acontece após o clique?

01

Botão

O site inicia o login pelo componente oficial.

02

Conta Google

A pessoa escolhe uma conta e confirma sua identidade.

03

Credencial

O Google retorna um ID Token: uma credencial digital de identidade.

04

Validação

Em produção, o servidor verifica a credencial antes de liberar o acesso.

A aplicação controla o acesso depois de validar a identidade.

As credenciais

ID Token e JWT

ID TOKEN · TOKEN DE IDENTIFICAÇÃO

O que o Google entrega

Uma credencial digital que contém informações sobre a pessoa que entrou.

JWT · JSON WEB TOKEN

O formato da credencial

Um formato de token que transporta dados. No login do Google, inclui uma assinatura digital.

JSON é um formato de texto que organiza informações em campos e valores.
Exemplo: "name": "Ana" relaciona o campo nome ao valor Ana.

Fonte: padrão JWT (RFC 7519)

A estrutura

As três partes do JWT

No ID Token do Google, as partes são separadas por pontos.

01

Header

Cabeçalho

Indica o algoritmo usado para assinar o token.

02

Payload

Conteúdo

Reúne os dados da identidade e da validade do token.

03

Signature

Assinatura digital

Permite verificar a origem e se os dados foram alterados.

Algoritmo é o método de cálculo usado na assinatura digital.

Os campos

O que significa sub?

sub vem de subject e identifica a conta à qual o token se refere.

Identificador da conta

No Google, é um identificador único e estável para aquela conta.

O sistema usa esse valor para reconhecer a mesma pessoa, mesmo que o e-mail mude.

EXEMPLO FICTÍCIO DE DADOS
{
  "name": "Ana Exemplo",
  "email": "ana@example.com",
  "sub": "1234567890"
}

name = nome · email = endereço de e-mail
sub = identificador da conta

Segurança

Como o servidor valida o token

O servidor é o sistema que verifica a credencial e protege os dados do site.

Assinatura

Confirma a origem e a integridade dos dados.

Emissor · iss

Quem emitiu a credencial. Neste caso, o Google.

Audiência · aud

Para qual site ou aplicativo o token foi emitido.

Expiração · exp

Até quando a credencial pode ser aceita.

Após a validação, a sessão mantém o usuário identificado entre solicitações ao site. As permissões definem o que ele pode acessar.

Fonte: documentação oficial do Google

Do conceito ao código · demo/script.js

Onde a API entra no site

02 / GOOGLE

Preparar o botão oficial

function renderGoogleButton() {
  if (!initialized) {
    google.accounts.id.initialize({
      client_id: CLIENT_ID,
      callback: receiveCredential,
      auto_select: false,
      ux_mode: 'popup'
    });
    initialized = true;
  }
  $('googleButton').replaceChildren();
  google.accounts.id.renderButton($('googleButton'), {
    theme: 'outline', size: 'large', width: 240, locale: 'pt-BR'
  });
}

initialize associa o Client ID ao site. renderButton desenha o botão oficial; o Google conduz a escolha da conta.

03 / RESPOSTA

Receber a credencial

function receiveCredential(response) {
  try {
    const profile = decodeProfile(response.credential);
    showProfile(profile, 'google');
  } catch {
    $('loginStatus').textContent = 'Não foi possível ler a credencial. Tente novamente.';
  }
}

O Google chama o callback com um ID Token. decodeProfile apenas lê e confere campos; não valida a assinatura nem cria uma sessão.

Esta ação usa um perfil fictício local. Ela não chama a API do Google nem autentica a pessoa.

04 / SITE

Mostrar os dados na tela

function showProfile(profile, mode) {
  profileVisible = true;
  $('profileName').textContent = profile.name;
  $('profileEmail').textContent = profile.email;
  $('profileInitials').textContent = profile.name.trim().split(/\s+/)
    .slice(0, 2).map(part => Array.from(part)[0] || '').join('');
  $('modeBadge').textContent = mode === 'demo'
    ? 'Simulação • perfil fictício'
    : 'Google • perfil recebido, sem validação no servidor';
  setPhoto(profile.picture, mode);
  $('loginView').hidden = true;
  $('dashboard').hidden = false;
  $('dashboardTitle').focus();
}

O site usa textContent para mostrar nome e e-mail, escolhe a foto e muda a interface. Nenhum recurso privado é protegido por esta tela.

Receber ou decodificar um token não substitui a validação no servidor.
