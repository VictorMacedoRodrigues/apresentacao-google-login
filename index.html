06 / Nos bastidores · 55 segundos

O que o Google devolveu?

Um ID Token, que é um JWT: uma credencial com partes codificadas e dados sobre a identidade.

ESTRUTURA ILUSTRATIVA DO TOKEN
headerCabeçalho
payloadDados
signatureAssinatura

O campo credential recebido no callback contém o JWT. Neste HTML, decodificamos o payload para apresentar a interface personalizada.

PAYLOAD · EXEMPLO FICTÍCIO
{ "name": "Pessoa Exemplo", "email": "pessoa@exemplo.com", "picture": "https://.../foto.jpg", "sub": "identificador-da-conta" }

Decodificar é diferente de validar a assinatura. Não mostramos o token real do usuário.

07 / Boas práticas · 55 segundos

O que torna esse login seguro em produção?

Usar o Google facilita a entrada, mas a segurança do acesso ao sistema continua sendo responsabilidade da aplicação.

O QUE NOSSO HTML FAZ

Uma demonstração didática

  1. Exibe o botão oficial de login.
  2. Recebe uma credencial no navegador.
  3. Interpreta campos para apresentar o perfil.
  4. Não guarda tokens nem protege dados privados.
O QUE UM SISTEMA REAL EXIGE

Verificação e sessão

  1. Enviar o ID Token por HTTPS ao servidor.
  2. Verificar assinatura, emissor, audiência e expiração.
  3. Identificar a conta pelo campo sub.
  4. Criar uma sessão segura e aplicar permissões.

O Client ID identifica o aplicativo: não é um Client Secret. E a senha do Google nunca é recebida pelo nosso site.
