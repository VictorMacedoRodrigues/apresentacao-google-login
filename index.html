Uma distinção importante

Identidade e permissões

AUTENTICAÇÃO

Quem é você?

Confirma a identidade
da pessoa que está entrando.

AUTORIZAÇÃO

O que você pode acessar?

Define quais dados e ações
ficam disponíveis para essa pessoa.

OpenID Connect trata de identidade.
OAuth 2.0 permite delegar autorização.

O serviço

Google Identity Services

Recursos do Google para integrar o login ao site.

Conta existente

A pessoa usa a própria conta Google.

Senha no Google

O site não recebe a senha dessa conta.

Perfil básico

O site pode receber nome, e-mail e foto.

Esse login, por si só, não concede acesso ao Gmail ou ao Drive.

O processo

O que acontece após o clique?

01

Botão

O site inicia o login pelo componente oficial.

02

Conta Google

A pessoa escolhe uma conta e confirma sua identidade.

03

Credencial

O Google retorna um ID Token para o site.

04

Validação

Em produção, o servidor verifica o token e cria a sessão.

A aplicação controla o acesso depois de validar a identidade.

A resposta

O que é o ID Token?

Uma credencial no formato JWT que contém informações sobre a identidade.

Estrutura do JWT

header.payload.signature

O payload reúne os dados.
A assinatura permite verificar
a autenticidade da credencial.

EXEMPLO FICTÍCIO DE DADOS
{
  "name": "Pessoa Exemplo",
  "email": "pessoa@example.com",
  "sub": "identificador-da-conta"
}

O campo sub identifica a conta.
O token real não será exibido na demonstração.

Segurança

O servidor precisa validar a credencial

  1. 01
    Verificar assinatura, emissor, audiência e expiração.
  2. 02
    Identificar a conta pelo sub e criar uma sessão segura.
  3. 03
    Aplicar as permissões de acesso da aplicação.

Ler os dados do token não substitui a validação.
